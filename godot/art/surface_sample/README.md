# Opening surface sample (bounded candidate)

This is an original, offline-generated **surface layer**, not completed island,
ship or cabin art. It addresses flat colour areas only. No external imagery,
models, downloads or dependencies are used. The three opaque RGB8 PNGs are
256 × 256; provenance, fixed seeds, exact hashes and decoded pixel statistics
are in `asset_manifest.json`. Code and generated assets use the repository's
AGPL-3.0 license (`LICENSE`). Existing assets and their licenses are unchanged.

## Reproduce / check

From the repository root, using Python 3 and its standard library only:

```sh
python tools/generate_surface_sample.py
python tools/generate_surface_sample.py --check
```

`--check` is read-only. The manifest records the generator's SHA-256, so a recipe
change requires an intentional manifest refresh. This second candidate changes
only mapping metadata; the three PNGs and import sidecars are byte-identical to
the first candidate. Godot's `.import` sidecars explicitly
request **lossless import and mipmaps**, without editor 3D auto-detection.
No texture or noise is generated during gameplay.

## Exact scope

- `IslandLandmass/Shoreline`, `IslandLandmass/Grassland`: shared sparse neutral
  mottling, respectively 1.8 m and 2.8 m local tiles; existing base colours remain.
  These two surfaces use ordinary UV mapping, not triplanar sampling.
- The unique direct mesh in `ArkRoot/RaftTop` and
  `ArkRoot/RaftBoardingGangplank`: the same grain with shallow colour-only seams,
  four lanes in a 1.48 m tile (0.37 m pitch, matching the existing cabin boards).
- `ArkRoot/BuiltShelter/CabinFloorboards/FloorPlank0..7`: grain only. The eight
  existing physical boards already have gaps; no duplicate seams are painted.

The terrain builder's final optional argument `surface_uv_xz = false` is
explicitly enabled only by the first island's construction call. It writes
`UV = Vector2(vertex.x, vertex.z)` in local meters before each original vertex:
+X follows +U and +Z follows +V. Existing scales remain `Vector3.ONE / 1.8` for
shore and `/ 2.8` for grass, giving matching density/direction across each mesh.
Normals are generated by the original construction path; there is no cloning,
vertex insertion or second mesh commit. Default calls (including the other four
islands) emit no UV array and retain their original path without mutable state.

The wood tile remains 1.48 m across local X and 3.2 m along local Z. All ten ship
meshes keep `StandardMaterial3D` **local** triplanar mapping. Every material keeps
`uv1_world_triplanar = false`, so textures follow mesh transforms rather than
remaining fixed in world space. There is no custom shader, normal/height/AO map,
transparency or second material pass. The helper still caches twelve duplicated
materials and three preloaded textures; world creation and cabin rebuild apply
them idempotently, with no frame-time update hook.

Only `albedo_texture`, `uv1_triplanar`, `uv1_scale` and the explicit false
`uv1_world_triplanar` are assigned. Original albedo colour, roughness, filtering,
triplanar sharpness, culling, illumination and all other material properties
remain as authored. Relative to the first candidate, the only material changes
are `uv1_triplanar = false` on the two terrain materials. The only mesh-attribute
changes are their added local-XZ UV arrays. Vertex positions, normals, indices,
triangles, bounds, collision, node names, transforms, interactions, save
format/state, simulation, weather and lighting are untouched. Other islands,
walls, roofs, trim, end-grain strips, furniture and characters are excluded.

## Multiplication and acceptance limits

A neutral albedo texture can **only darken** its base. These sparse textures
retain byte 255 as the median. Mean linear multipliers are approximately 0.989
(terrain), 0.991 (grain), and 0.988 (deck); these are decoded texture statistics,
**not rendered luminance or performance guarantees**. No exposure or night-light
compensation is included. The sloping shore uses the same top-down XZ projection;
it does not add side projection samples. Side faces of the ten allowed ship
meshes keep their existing triplanar material. No geometry or extra surface is
introduced to mask them.

Real normal-camera day/night/storm comparisons must independently establish a
visible benefit without harming readability. Headless tests establish only
logic, property preservation, scope and resource availability. Performance must
be measured separately. The first all-triplanar candidate's fixed 16-run cloud
llvmpipe comparison showed roughly 9–11% higher pooled coast median frame
intervals, with the regression present in both AB and BA orders. That measured
cost motivates replacing the two large terrain surfaces' three-way sampling
with ordinary single-projection UV sampling, while leaving ship mapping alone.
This is an optimization hypothesis, not a measured performance win: the second
candidate still needs independent rendering and timing checks. Software-renderer
frame intervals are not pure GPU time or a hardware FPS guarantee. If the subtle
candidate is invisible, too dark or still too costly, reject/review it rather
than quietly expanding scope.
