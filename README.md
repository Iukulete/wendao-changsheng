# 问道：归舟

Godot 4.7.1 标准版 GDScript 的 3D 开放世界仙舟家园原型。

从木板与旧灯起步，建造可进入的家，与居民生活、修理、采集、共餐；驾驶
仙舟停泊、扩建，探索浅滩、远礁与更远的海域。当前是有限手工海域切片，
不是已经完成的大型开放世界或最终美术版本。

当前仍为 **0.1.003 开发迭代**，已接入按家中缺口采集、储粮搬运/烹饪、
授权持续修缮、逐步补齐的家园模板、灯下21点与可选现代太阳能/净水生活链。
首岛岩脊、月背环坡与旧栈桥有真实地面/碰撞和有限探索收益；学会的蓝图永久保留。
甲板、帆布、暖木生活舱与现代设备使用统一美术样板，人物和建筑细节仍是原型水平。

水面保留 Gerstner 位移/查询与地形深浅着色，仍不支持折射、SSR 或物体倒影。
部分旧路线和岸线接缝仍需整理；没有完整游泳AI、通用电网、任意房间识别或大量NPC验收。
共餐、修缮、炊事与现代洗漱须真实到位并结算，叙事只记录实际完成的事实；
风暴/开船的旧紧急召回仍保留直接召回策略，不能当作所有情况下都真实走回。
本地 headless 验证不等于最终美术或 Windows 硬件帧率验收；修改记录、核验范围和限制见
[持续工作状态](docs/ARK_WORKFLOW_STATUS.md)。

## 游戏版本

当前游戏版本为 **0.1.003**；唯一机器可读来源是
`godot/project.godot` 的 `application/config/version` 字符串，菜单与构建元数据均读取它。
采用自定义 **S.X.Y**（不是 SemVer）：S 为 0 起不限上界的玩法/内容大版本；
X 为 0–9 阶段位（1 基础版本、3 基本玩法、5 主要玩法、7 Alpha、8 Beta、9 RC）；
Y 为 000–999 修复位，必须保留三位前导零。不据此推定已有历史发布。
游戏版本与 Godot 引擎版本、存档 schema、外层格式及产品识别标记分别管理。
Windows 构建生成 `game-version.json`，纳入校验和并与工程版本核对。

## 启动与验证

固定使用官方 **Godot 4.7.1 Stable 标准版**，不需要 .NET；验证需要 Python 3。
Windows 将项目、引擎与缓存放在可写的 D 盘工作目录：

```powershell
./tools/prepare_godot.ps1 -SkipTemplates
./tools/godot/4.7.1/Godot_v4.7.1-stable_win64.exe --path ./godot
./tools/verify_godot.ps1 -NoPrepare
```

跨平台验证使用已下载并核验的同版本引擎：

```sh
python tools/verify_godot.py --godot /absolute/path/to/Godot_v4.7.1-stable_linux.x86_64
```

`启动游戏.bat` 可启动本地构建或工程；`构建Godot版.bat` 构建 Windows 包。
如果已手动下载官方标准版 `Godot_v4.7.1-stable_win64.exe`，可将它放在
`启动游戏.bat` 旁边，直接双击启动，无需先构建导出包或下载导出模板。
最终资源和画面须分别进行真实渲染与导出包检查；headless 通过不代表美术
或硬件帧率验收通过。

## 基本操作

- WASD：正常行走/游泳；按住 Shift：地面快跑；Space：跳跃。
- E：附近互动/舵位；Q：近身攻击。新档风雨预报期即可掌舵，不必先建棚或经历风暴；E/Esc 离舵停船后可上岸采集，材料带回随船家园建造。
- B：建造；F：附近储物箱/工作台编辑；编辑中 R：旋转。
- 鼠标左键确认施工；右键或 Esc 取消；M：潮痕图；F5：保存。
- 普通探索按住右键拖动旋转镜头，滚轮缩放，Home复位；WASD随镜头朝向移动。
- H：操作/建造抽屉；G：储箱旁管理家庭食材；F7：临时切换家园美术/灰盒对照。
- F8：实际FPS与近似帧时间/绘制调用，不是独立GPU计时或大量NPC性能保证。
- 原型中 R（非编辑状态）控制天气阶段，T 推进时段；不是最终时间系统。

更完整的控制、家园岗位、储粮与现代设备说明见 [Windows玩法说明](docs/WINDOWS_RELEASE_README.md)。

生活舱首轮家具样板复用[KayKit Furniture Bits的免费CC0子集](https://github.com/KayKit-Game-Assets/KayKit-Furniture-Bits-1.0)：
只取床、柜、书三模型，统一颜色与粗糙度，原文件、图集和许可保留。家具必须随原设施建成，
不会免费扩背包或增加居民床位；原休息和储粮逻辑不变。进入舱室时，实际挡住相机视线的
墙面、布檐和门梁让开，墙脚保留矮轮廓；邻舱前景屋顶也可让出视线，碰撞与损伤状态不变。
开局是捆扎原木浮体，真正建成龙骨扩甲后才换为成形船壳；舵位用实体舵轮替代占位标杆。
F7可恢复原视觉。家具尺度、建筑轮廓、人物、其他岛区和界面仍需打磨，不是整套美术完成版。

## 存档与兼容

3D 独立存档保持 `res://../.local/save/ark_greybox_v1.json` 的历史解析位置，

如需回退程序版本，请事先单独保留未升级的存档副本。

未来版本或不能安全读取的旧档会保留，并显示未保存会话提示，不静默重置。
测试必须使用独立路径，禁止指向真实 `.local/save`。

### 本轮恢复的可玩边界

- `H` 或右上角按钮展开帮助/建造抽屉，`Esc` 优先收起；关键状态和保存失败不会被隐藏。
- 默认使用素材目录提供的 Emma 3D 骨骼模型，像素候选保留但不是当前默认方向；F8现用于性能面板。Emma 使用 Quaternius CC0 成品待机、行走、快跑和游泳动画，尚未接入表情或头发物理；碰撞、移动和存档沿用现有控制器。模型来源和接入限制见 [Emma 接入说明](docs/EMMA_MODEL_INTEGRATION.md)。
- 共餐需要实际食材、居民到桌和玩家在场按 `E`；离开、风暴、航行或时段变化会暂停，返回后需主动恢复。
- 新游戏使用 Gerstner 波；旧存档保留原解析波模型，避免读档时切换海面。船体仍沿用原有受控悬浮设定，不宣称真实排水船体模拟。
- 可选 C++/双工作线程水体批计算保留 GDScript 参考回退，默认不启用原生后端。构建步骤见 `native/ark_water/README.md`；Linux 验证不代表 Windows DLL 已验证。
- 建造、资源账本、采集任务和事实记忆已分离为增量模块；部分旧场景标量仍通过显式兼容命令同步，并非完整重写。
- C++/Flecs居民工作内核在`native/ark_simulation`，Windows构建脚本会构建并验证随包库；开发端缺库可使用参考实现，协议故障不会静默换内核继续扣料。这不是全部玩法已经原生化或大量ECS人群完成。

### 生活时钟与岸边补给

每个昼夜时段在约 180 秒在线活动后自动推进，帮助、地图、建造及待确认选择暂停时钟；T/床铺仍可主动推进并重置当前时段计时。不按现实离线时间补算，风雨仍由 R 推进。每次跨入清晨，固定岸边漂木与潮贝点只在采空、无人预留或搬运时补回原来一批，不累积未采库存、不刷新唯一遗迹奖励。补给进入世界资源账，须实际采集；旧档从下一个清晨开始使用此规则。

### 起居工坊模板

在 `H` 操作/建造抽屉选择“起居工坊”，空地整套7木，也可保留既有棚屋/床/家具，只补缺少部分。
整套占地、人物安全位置、固定灯与通路均先校验，确认时通过同一事务扣料；取消不扣料。
建成后箱子与工作台仍可搬移/旋转，随舟航行并保存恢复；模板不增加人口容量，也不新增资源来源。
原5木潮棚之家共用组合通路校验；已有棚后补箱2木，再补工作台2木，不重复建造或重置已有设施。

基础棚定位为临时避难所：两处临时接纳空间不等于两张居民床，玩家床铺另计。
居民专用铺位随甲板扩建、客舱从 0 增至 1、2；原接纳容量 2、3、4 与建造成本不变。
夜间及风雨时，两位居民使用不同的临时避风点，不再把玩家床铺作为夜间终点。
共餐垫与就座点保持原尺寸重新排布，共餐路径绕开床铺和火盆；旧档重叠位置通过行走恢复。
缝帆人的雨檐贡献需要实际缝制、搬运和安装；可保存中途进度，遇到风雨、航行、共餐或夜间会暂停。
安装时实际举布，旧雨檐挂点提高并延长支撑，避开落成、夜间避风和共餐的头部；棚屋与布面尺寸不变。
共餐和缝帆工作路径避开床铺与火盆；这不包含新增躺卧动画，其他路线及玩家穿行非实体床铺的既有行为仍需后续整理。
后续按[持续工作流](docs/ARK_ITERATION_PLAN.md)推进；资源补给政策仍单独评审，不以测试通过代替设计认可。

### 局部可读性与输入修正

靠近基础棚口或进入棚内时，中央棚顶及其附着细节暂时让开视线，窄檐、柱墙和入口布檐保留，离开后恢复。
附近的守潮人、缝帆人及火盆名称在该局部切面中错开显示，离开或重建后恢复原位置；镜头、交互和存档格式不变。
这是原型可读性处理，不是最终美术或完整 HUD 重设计，普通家具和远处文字仍有后续整理空间。
同场景重复读档不再叠加棚屋及其交互点；读取未建造存档会清除旧棚屋。地面 Space 跳跃不再被下一物理帧的落地偏置抵消。

蒸汽遗迹以真实喷口为中心显示固定 2.9 米警示边界，圈只改变亮度，不再用缩放动画误导安全距离；离开圈外可避开该次爆发。
警示与伤害使用同一实际喷口位置，喷口卸载后不留下危险；原蓄压、冷却、伤害、唯一核心及饭釜成长规则保留。
