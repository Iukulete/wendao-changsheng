# 归舟 3D 仙舟原型：稳定性与资源呈现检查

## 范围

本轮只面向 `ark_greybox.tscn` 的连续 3D 世界、移动仙舟家园、建造、
居民自主生活、探索危险和独立存档。基线为家具编辑 PR #12 的 `3d9903b`。

旧 2D 六纪元、技能卡片战斗、旧剧情界面及其图像/音频不作为本轮继续
开发的产品。保留其源码、原文、稳定 ID 与资源；全仓回归仅用于确认新改动
没有破坏保留内容，不代表旧玩法重新成为方向。旧正文未来接入新世界须
另行审阅。私人交接文件未纳入仓库或本报告。

## 已复现并修复

- 船头扩建未计入航行碰撞查询：同步扩展船体查询并保留旋转后的占地。
- 居民寻路将甲板外的空水面当作可走位置：增加甲板支撑边界；拒绝
  非有限、越界和超大跨度的寻路端点，限制网格规模。
- 地图/选择面板未隔离世界快捷键：地图打开时不再推进天气等后台动作，
  补齐取消操作。
- 施工和掌舵可以同时激活：双向校验进入条件。
- 同帧拆除后重建产生自动改名节点，导致后续设施访问失败：先从场景树
  脱离退役节点，再延迟释放，并失效移除甲板的居民路线。
- 礁流/压力蒸汽击退在下一帧被移动速度覆盖：采用衰减冲量，并在救回舟上
  或切换掌舵时清除残余力。
- 新建造预览的大面板遮挡甲板：与家具编辑一致使用紧凑施工状态、材料与
  操作提示，退出后恢复普通 HUD。
- 坏主档可能替换唯一好备份：仅轮换已校验主档，坏文件隔离；备份恢复后
  修复主档；先验证临时写入再提交。
- 未来版本/不可读档可能静默覆盖：保护原档，并明确显示本次未保存会话
  和手动保存失败；覆盖地图、家具编辑等 F5 路径。
- 畸形/非有限字段与过大文件可能造成载入错误：有界类型检查、字段恢复；
  保留历史存档目录和缺省字段的兼容行为。

## 验证方法

新增独立 Ark 回归覆盖导航、输入模式、拆建资源守恒、实际危险位移、
存档备份与损坏恢复、旧档字段与未保存提示。所有测试使用隔离存档目录。

地形测试的旧月背东岸采样点落在波状海岸网格外，并非碰撞缺洞：移到
实际斜岸内，增加岸外水面反断言，并纳入常规验证。未为迎合测试改地形。

使用官方 Godot 4.7.1 标准版；退出码、错误日志和成功标记三者同时检查。
实际渲染使用云端 GL Compatibility / Mesa llvmpipe，不能代表目标显卡性能。

## 最终结果

本检查点已通过官方 Godot 4.7.1 的 49 项完整回归及 5 项资源/内容检查；
随后标签布局单项回归另行通过，覆盖 1280×720、1440×900、800×720、
移动家园地点与逐个标签点击。此结果仅对应稳定性检查点，后续旧系统退休
须重新运行 Ark 专用完整验证，不沿用这组结果冒充退休后的验证。

- 潮痕图标签采用避让与引导线，预留保存提示区域；船上标注提高可读性、
  精简重复字幕、错开居民名字；舵位互动提示明确掌舵操作。

## 保留边界

- 当前仍是小型手工海域，不是已完成的大型开放世界。
- 程序化人物/岛屿和临时海面仍为占位；旧肖像或概念图不等于正式3D模型。
- 未进行全设备/全驱动或 Windows 可执行版本的实机验收。
- 未注入真实磁盘写满或断电；错误写入与原档保护以隔离故障用例检查。
- 本轮未新增整套战斗、修为、居民关系或料理系统；美味烧鸡仍是生活内容
  候选，不与修复混在一起。
- 修复通过独立分支交付，不自动合入共享分支或 main。
