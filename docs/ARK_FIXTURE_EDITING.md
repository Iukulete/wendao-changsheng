# 储物箱与工作台布置

## 玩家操作

在 `godot/scenes/ark_greybox.tscn` 中，靠近已建成的储物箱或阵枢工作台：

- `F`：进入家具布置。设施标牌与近距离互动提示会显示入口。
- 鼠标：在甲板上选择位置，按 0.5 米网格吸附。
- `R`：每次旋转 90°；只在家具编辑中改变朝向，正常玩法仍用 R 推进天气。
- 左键：确认绿色合法预览。
- 右键或 `Esc`：取消。编辑时再次按 F 或 B 也会取消。
- `F5`：保存已经确认的世界状态；预览不是第二件家具，不进入存档。

绿色/红色预览与文字说明一起反馈结果。预览中的凸起边表示朝向；原设施仍留在原位，取消不会丢失库存或设施。确认是对同一模型、碰撞和交互标记的变换，不走重新施工或拆解流程。

## 本轮范围

只编辑已有储物箱和工作台，限原始甲板。扩建甲板、客舱、床位与拆除有独立生命周期，本轮不允许把家具移到那些区域，不宣称完成通用房间编辑器。

检查旋转后的完整占地、棚屋、另一件家具、固定灯座、当前人物位置，以及从舵位一侧到居民返回点、棚门、扩建入口及家具可用侧的通路。柜盖和桌面没有只准从正面使用的限制。碰撞与居民路径随新布局更新。旋转仅有四种离散方向，不提供任意角度。

搬移不收取/返还材料，不改变 `wood`、`stored_wood`、工作台升级或已学蓝图。设施保持 `ArkRoot` 局部坐标，仙舟航行与转向仍携带家具和互动点。

## 代码与存档

- `ark_fixture_placement.gd`：旋转归一化、占地、边界和几何规则。
- `ark_greybox.gd`：编辑状态、输入/预览、世界通路检查、实体变换、居民重新寻路与保存编排。
- `ark_fixture_edit_test.gd`：搬移行为定向回归。

内层状态 schema 从 32 升至 33；外层保存格式仍为 1。新增 `storage_quarter_turns`、`workbench_quarter_turns`，按 0–3 表示相对甲板的 90° 旋转次数。schema 32 及以前读为 0，保持旧方向；异常朝向类型安全回退为 0。位置字段与设施 ID 不变。保存的是确认后的状态，不是鼠标预览状态。

兼容旧布局时，不直接为所有旧家具强加实体碰撞：过去允许的紧凑布局可能因此堵住居民去铺位的路线。`storage_collision_enabled` / `workbench_collision_enabled` 缺省为 false，保留旧的非阻挡行为；经过本轮完整落位校验并确认搬移后，对应设施才启用实体碰撞并保存该状态。不会为了迁移偷偷挪动玩家的家具。

## 验证入口

Windows 沿用仓库 `tools/verify_godot.ps1 -NoPrepare`。Windows 项目和测试数据仍须在 D 盘。

云端 POSIX 环境使用已校验的官方 **Godot 4.7.1 标准版**：

```bash
python tools/verify_godot.py --godot /absolute/path/to/Godot_v4.7.1-stable_linux.x86_64
python -m unittest discover -s tools -p test_verify_godot.py
```

Python 入口从 PowerShell 的测试清单读取回归项，检查版本、错误日志、退出码、成功标记与超时；不会下载引擎或替换版本。测试存档必须是当前仓库 `.local/test_*` 下独立目录，不能使用正常玩家 `.local/save`。日志与云端运行缓存放在仓库 `.tmp/godot-verify/`。

实际运行结果、渲染评审和未完成验证在本轮交付记录中另行说明；上述命令本身不代表通过。
