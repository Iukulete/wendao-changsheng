# 《问道：归舟》Windows 原型

完整解压到可写的 D 盘目录，运行 `运行归舟.bat`。它把运行缓存、临时文件与日志留在包旁的 D 盘目录。
不要只复制 EXE，直接运行 EXE 可能使用 Windows 默认的 C 盘日志/用户缓存路径。
当前入口仅是3D仙舟家园，不再提供旧六纪元或卡片战斗。

建议窗口至少1280×720。WASD行走/游泳，Shift地面快跑，Space跳跃，E互动/掌舵，Q近身攻击，
B建造，F编辑附近储物箱/工作台，编辑中R旋转，G在储箱边管理家庭食材，M地图，F5保存。
H 中的潮棚之家/起居工坊支持逐步补齐：已有棚屋、床和家具不重建，只付缺少部分的木料；
基础棚后补储箱2木，再补工作台2木。材料不够也能先预览，取消不付料。
新建潮棚会预留工作台位置；旧版或自定义布局若挡路，预览会提示先用F搬家具，不自动改动原布置。
建造时鼠标左键确认、右键/Esc取消。非编辑状态R/T是原型天气/时段控制。
普通探索时按住鼠标右键拖动旋转镜头，滚轮缩放，Home 恢复默认视角。
WASD 随镜头朝向移动；地图、建造和对话打开时不抢鼠标输入。
F8 显示/隐藏实际 FPS、近似平均帧时间、Process 时间和绘制调用；它不代表 GPU 独立计时或卡顿峰值。
默认启用甲板木作、灰青收边、帆布生活舱与现代水台的统一美术样板；F7 临时切换灰盒对照。
此切换不改物资、水电、居民动作、碰撞或存档；重新进入游戏恢复默认样板。
床铺、储粮柜与付料客舱现使用同色系3D家具样板，仍保留原休息、G食物/E木料存取和容量。
舱内按实际相机视线让开遮挡的墙面、门梁和布檐，墙脚留矮轮廓；前景屋顶也可为邻舱让开。
这仅改变视觉，不移除墙体碰撞、工作房间或风暴损伤；离开/F7恢复，右键仍可自由转镜头。
开局原木浮体在真实龙骨扩甲后升级为成形船壳，船尾登船口保留；舵位有实体舵轮，不再用金色标杆。
KayKit免费CC0模型的作者/来源/原始许可随PCK保留。整套场景、人物与UI还不是完成版美术。

存档沿用原型 `res://../.local/save/ark_greybox_v1.json` 解析位置。
移动或升级前备份对应 `.local/save`（包括主档、备份与隔离坏档），不要
假设它与历史六纪元的 `save/` 通用；没有自动旧进度转换或重置按钮。
提示“临时试玩/不会保存”时先保留旧文件，用匹配版本检查，不反复覆盖。

H 抽屉中的“居民分工 / 房间用途”可授权缝帆人持续修缮。必须有真实损坏、工作台与储木，
居民到位工作，完工才扣料；夜间、风雨、航行、建造和共餐暂停，不会拿随身材料。

守潮人的默认采集方针是“按家中缺口”：先为缺少的储箱备木；有储箱后优先备两份口粮，
再筹工作台或两块备用木料。家中储备已够就休息，每天仍最多一趟，不补离线产出。
已扩甲并真正回收现代蓝图/组件后，才会改为筹四木设备材料；安装仍由玩家决定并付料。
家园受损时仅在安全清晨补缺少的储木，够修就等；自动补木不等于自动授权修缮。
与守潮人交谈也可指定木料/鲜贝优先，影响下一趟；指定偏好会继续收集，不以自动储备目标停工。
H详情或居民分工面板可查缺口；只算本家已到手物资，不把在途货物或其他仙舟库存当成可用储备。

和居民真正共餐后，可在棚内桌边从 H →“灯下牌局”邀请在场居民，玩无物资输赢的21点。
鼠标点击或1要牌/再开一局、2停牌；Esc暂离，F5保存。未结束的牌局会保留原牌序，
读档或暂离不会重洗。普通对话也有固定的可点击选项，长正文仍可独立滚动。
内部存档升级到schema43；旧档不会凭空增加储粮、共餐、牌局、炊事或现代设备经历。

储物箱另有8格家庭储粮，不占原有储木。居民采回的鲜贝会实际送到储箱，不再直接放进玩家背包。
靠近储箱按G：1存随身食物（热汤优先）、2取1份汤、3取1份鲜贝，Esc关闭；E仍只存取木料。
守潮人安全傍晚优先到储粮格取1份鲜贝，用食篮带到真实锅边：普通炉灶4秒、蒸汽饭釜2秒有效
工作，完工才把原料变成1热汤，再走回储箱入库。没送到时汤仍在她的食篮，不能远程取用。
每天最多一锅，已有两份则不囤做；没有箱内食材时仍兼容旧版随身供料。H →“炊事岗位”可暂停。
菜单、施工、阻路、缺料、夜间、风暴、航行、共餐或修缮会暂停未完成工作；退料/送汤会在安全时
继续收尾。途中退出会保留物资和进度，不补离线产出。储粮满时居民保留货物，按G取出腾位后继续。
取出热汤后仍可到桌边邀请居民共餐，必须等人实际到齐；玩家原手动配方不变，不增加水电门槛。

现代设施可在最终仙舟形成前逐步发展。蒸潮机坞的隔水舱可一次性回收供电净水组件，同时永久学会“日照净水角”。旧档已搜索过
该遗迹的，需再到现场查看，不会读档就送设备。建好龙骨甲板后，回到本舟，在 H 中用
4 木和这套组件安装。白天按天气蓄电；停泊且取水口在水中时，每份清水花 2500 电量，
储罐上限 6 份。航行时只发电不净水；可从 H 暂停净水来留电。到台旁按 E 温水洗漱，
每天一次，花 1 水和 500 电量，恢复 1 点生命、缓解一层寒冷，不推进时间。
守潮人和缝帆人在安全的上午/白天空闲时，会轮流走到水台洗漱；真实到位并完成两秒动作后，
每人每天花 1 水和 500 电量。采集、修缮、私人雨檐、共餐、避灾与夜歇优先；缺水缺电则不执行。
中途离开、进入施工/菜单或读档会清空未完成的动作，不重复收费，也不凭空增加生活记忆。
走到水台旁，从 H 点“收纳日照净水角”并再次确认，可收回4木和同一套设备组件，再另行拆甲板。
收纳时彻底停机，但封存电量、清水、滤水进度和每日洗漱记录；重装仍需4木和组件，不刷新收益。
人在使用水台、航行/施工/游泳或离开水台后不能收纳；返还容量不足时材料、设备与水电均不变。
原煮汤与睡眠不加水电门槛。

月背东北的旧栈桥可接船尾，岸边有有限漂木与鲜贝；仍可从其他北岸登陆后沿西侧步道登高。
安全上午停在接岸的合适位置，守潮人会先确认真实通路，再走出去采集并将货物带回。
归路被挡就等候，不会隔海入库；旧有风暴/开船紧急召回仍采用原型的直接召回策略。
这两个补给点仍按原规则在后续清晨补充，学会的蓝图和唯一潮枢不会因此刷新。

`native/` 为随包 C++ / Flecs 居民工作内核，完整解压，不要只复制 EXE 和 PCK。
H 功能板显示当前原生/参考后端。开发环境可用
`python native/ark_simulation/build.py --godot <Godot控制台EXE路径>` 在 D 盘构建，
默认复用 `D:/msys64/ucrt64/bin` 的 GCC；也可显式传 `--cc` / `--cxx`。
无库时可用参考实现启动；中途原生协议异常会停工，不会静默换内核继续扣料。

当前仍是局部统一美术/占位人物混合的区域原型，非最终画质或完整大世界。发布包只含实际活跃资源及字体、图标、AGPL/Flecs许可，
不含旧剧情库、旧立绘/音源、测试、引擎下载或个人存档。
公共主线源码与构建脚本见 https://github.com/Iukulete/wendao-changsheng/tree/main 。
本地开发迭代可能领先公共分支；分享独立二进制时应同时提供实际对应源码版本与本包许可文件，
不要把会继续变化的main链接当成固定构建的源码备份。本地发布包本身也不是完整仓库备份。
