# 旧系统退休边界与源资产保留

当前唯一活跃产品是《问道：归舟》3D 移动仙舟原型。旧卡片战斗、六纪元 UI、
旧主菜单入口与本地 AI 事件运行时已退休；保留创作资料不等于保留旧产品。

## 保留 / 移除

- **当前运行时保留：** Ark 场景、脚本、专用测试、新菜单与世界图；两套 Noto 中文
  字体、各自的导入配置、OFL 许可及 `font_manifest.json` 原地保留并在新菜单使用。
- **项目外保留：** `archive/source_assets/` 镜像旧数据、美术和音频原路径；剧情、
  人物稳定 ID、对白、图像、音频、许可证和来源清单按原字节保存。
  2D 肖像/概念/候选稿是未来参考与 staging，不是已完成的 3D 人物或场景。
- **仅资料保留：** 旧卡片、战斗数值、怪物队列和旧音频总线；禁止当作新动作战斗
  的约束或重新挂入活跃项目。旧内容工具移至 `archive/tools/`，不属于当前工具链。
- **移除：** 旧 `.gd`/场景/旧专用测试与旧启动面、旧本地 AI 安装/推理/训练/评估
  脚本，以及旧资源导入元数据。代码可从 Git 基线恢复，不另建可运行的旧产品副本。
  原有 AI 示例数据/来源说明继续保留；内嵌创作文字另作带来源的静态 JSON 摘录，
  不恢复 AI 脚本。本机模型、缓存、凭据等不在此次操作范围。
- **许可证不删除：** 项目 AGPL、字体 OFL、音频各项实际许可和署名记录保持完整。
  未核实权利的 curated 图仅供参考；生成来源记录也不是版权授权。

## 新旧存档

当前 Ark 继续使用专用 `ark_greybox_v1.json` 格式及自身校验/备份流程。
**没有旧卡片/六纪元存档转换器，也不把旧存档解释为新存档。** 此次退休不扫描、
改写或删除用户旧存档；若将来需要转换，须另设显式、可回滚的转换设计与验收。

## 复用顺序

1. 从原档案选定一段剧情、一位人物或一个音频，先核对版权/许可、署名和来源。
2. 核对新世界的地点、时代、年龄、人物关系与后果；保留来源 ID，另建适配映射。
3. 为新 3D 呈现单独制作模型/绑定/动作及交互；旧肖像不替代这项工作。
4. 只把审过的副本接入新运行时，并补充功能、性能、读档与版权展示测试。
5. 未选中/未通过的资产继续留在 Godot 根外，不打包、不加载、不重启旧机制。

## 验证与回滚

`python tools/verify_source_archive.py` 独立验证源文件哈希、JSON/JSONL 和稳定身份
关系，不依赖已删除的旧游戏。完整清单、用途分类与权利门槛见
[`archive/README.md`](../archive/README.md)。当前发布检查还应确认项目/导出不依赖档案。

退休前可回溯基线为 `3d9903b71c45560e631db96d2f2dd79f52b891d1`。
如需取证，在隔离 worktree 中检出该提交；不要在当前分支整树回退、覆盖用户存档，
也不要从旧版本拼回主菜单、卡片或六纪元运行时。源档案的原始字节保持不可变；
新的创作修改写入单独适配文件并记录来源。
