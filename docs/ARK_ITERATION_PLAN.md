# 仙舟家园：迭代与验收计划

本页记录开发顺序和验收要求，不是已完成功能清单。产品目标是开放世界里的移动家园：空间可经营、居民会自主生活、探索所得能改变日常。

## 交付规则

- 每轮从 `codex/island-survival-slice` 的实际最新基线建立独立开发分支，向该协作分支提交可评审 PR；不直接合入或重写共享分支。
- 一轮只完成一段可玩的变化，记录玩家操作、变更范围、存档兼容、验证证据和剩余限制。未经实际运行的检查不标为通过。
- 逻辑回归、真实渲染、人工观感分别记录。截图不证明行为正确，headless 测试也不证明画面品质。
- 保留旧剧情原文与稳定 ID；不把旧管理页当作新的开放世界入口。
- 资源先核验许可、来源、修改与再分发条件，再纳入版本管理。不提交个人存档、缓存、工具二进制或私人交接资料，不擅自购买资产。

## 第一轮：整理已有家具

范围：已有储物箱和工作台的选择、搬移、四分之一圈旋转、合法性预览、确认与取消。

验收：

- 玩家能在设施旁发现编辑入口，操作提示明确；原物件在预览时保留功能。
- 合法落位更新模型、碰撞、交互点及相关居民路径；非法落位说明原因，不消耗材料。
- 取消不改变位置、库存、工作台进度或蓝图；确认不复制家具、不收取二次材料。
- 检查旋转后的占地、承重边界、现有物体、必要通道和人物安全位置。
- 航行后仍按甲板局部坐标随舟移动；新档保留朝向，旧档有明确朝向缺省值。
- 定向回归之外，重新检查居民出工/回家、原有建造、航行和保存流程。

## 后续小步交付

| 轮次 | 玩家能感受到的变化 | 开工前核对 | 完成证据 |
| --- | --- | --- | --- |
| 房间与模板 | 选择完整起居方案后仍能调整家具，居民使用真实床位 | 设施配置、占地、材料与床位容量的事实来源 | 模板预览/取消、通路、容量、保存与居民使用回归 |
| 第二居民营生 | 不逐次派工也能看到另一位居民出门、带回物资并休息 | 已有共餐与独立日程，防止重复系统 | 有限资源认领、出工/回家、空目标取消、航行召回与读档中断恢复 |
| 探索成长 | 新海岸带来新路线或生活便利，而不是等级门 | 地点/资源稳定 ID、风险提示、撤退路线 | 真实往返路线、奖励唯一性、发现记录与保存 |
| 环境视觉样板 | 同一处海岸、甲板和居室具有一致的材料、暖冷光与生活痕迹 | 当前渲染后端、目标硬件、资源许可与尺度 | 固定机位前后对比、昼夜/风雨、遮挡、性能记录；风格评审后才扩区 |
| 后续扩展 | 更多舱室、生活设施、地区与仙舟社会 | 前轮反馈和系统边界 | 每次保留一个可独立验收的生活或探索闭环 |

## 美术资源进入游戏的门禁

1. 建立资源记录：来源、作者、许可证、原始校验、改动、项目中的用途。
2. 先在样板中验证比例、轮廓、UV/材质、碰撞、遮挡和远近景可读性。
3. 角色需要可动模型与适配动作；概念图不直接算作游戏角色，不能用换色代替人物差异。
4. 记录渲染后端、分辨率、硬件/软件渲染条件和帧时间；没有目标机器实测时明确保留限制。
5. 先提交候选样板供评审，通过后再做批量替换。不会仅以更大贴图分辨率宣称品质升级。

后续任务在每轮评审后按反馈调整，避免同时重写建造、居民、地图和渲染基础设施。
