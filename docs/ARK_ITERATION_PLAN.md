# 仙舟家园：迭代与验收计划

本页记录开发顺序和验收要求，不是已完成功能清单。当前证据、缺口和唯一活跃里程碑见 [持续工作状态](ARK_WORKFLOW_STATUS.md)。产品目标是开放世界里的移动家园：空间可经营、居民会自主生活、探索所得能改变日常。

## 交付规则

- 开工先核对实际仓库、分支、基线及未提交修改；保留用户与其他开发者的工作，不重置或覆盖。继续已有任务优先沿用其工作区，不机械从旧协作基线重开。
- 本地实施、提交、推送、PR、合并分别遵守当次授权；“继续开发”不自动授权发布。只有获得相应授权后才提交/推送或创建 PR，并核对目标分支；不直接合入、强推或重写共享分支。
- 一轮只完成一段可玩的变化，记录玩家操作、变更范围、存档兼容、验证证据和剩余限制。未经实际运行的检查不标为通过。
- 逻辑回归、真实渲染、人工观感分别记录。截图不证明行为正确，headless 测试也不证明画面品质。
- 保留旧剧情原文与稳定 ID；不把旧管理页当作新的开放世界入口。
- 资源先核验许可、来源、修改与再分发条件，再纳入版本管理。不提交个人存档、缓存、工具二进制或私人交接资料，不擅自购买资产。

## 已有基础：整理已有家具（保留回归，不重复立项）

现有 `ark_fixture_edit_test.gd` 已有通过记录；以下继续作为回归约束，不代表今天重新运行过。

范围：已有储物箱和工作台的选择、搬移、四分之一圈旋转、合法性预览、确认与取消。

验收：

- 玩家能在设施旁发现编辑入口，操作提示明确；原物件在预览时保留功能。
- 合法落位更新模型、碰撞、交互点及相关居民路径；非法落位说明原因，不消耗材料。

- 航行后仍按甲板局部坐标随舟移动；新档保留朝向，旧档有明确朝向缺省值。
- 定向回归之外，重新检查居民出工/回家、原有建造、航行和保存流程。

## 按原大纲继续的小步交付

先按“行为基线 → 必要边界与建造完整链路 → 采集与存档 → 风险 A/B/C → 最小修正和回归 → 交付”核对证据；已完成的提取不重做。架构验证场景不是远期玩法已交付的证明。之后沿下面顺序，一次只激活一个有界里程碑。

| 轮次 | 玩家能感受到的变化 | 开工前核对 | 完成证据 |
| --- | --- | --- | --- |
| 房间与模板 | 选择完整起居方案后仍能调整家具，居民使用真实床位 | 设施配置、占地、材料与床位容量的事实来源 | 模板预览/取消、通路、容量、保存与居民使用回归 |
| 第二居民营生 | 不逐次派工也能看到另一位居民出门、带回物资并休息 | 已有共餐与独立日程，防止重复系统 | 有限资源认领、出工/回家、空目标取消、航行召回与读档中断恢复 |
| 探索成长 | 新海岸带来新路线或生活便利，而不是等级门 | 地点/资源稳定 ID、风险提示、撤退路线 | 真实往返路线、奖励唯一性、发现记录与保存 |
| 环境视觉样板 | 同一处海岸、甲板和居室具有一致的材料、暖冷光与生活痕迹 | 当前渲染后端、目标硬件、资源许可与尺度 | 固定机位前后对比、昼夜/风雨、遮挡、性能记录；风格评审后才扩区 |
| 后期系统 | 多层船舱、多仙舟产业、餐饮/牌局、跨时代地区与经审阅的旧故事 | 前轮反馈和系统边界 | 每次保留一个可独立验收的生活或探索闭环 |

## 美术资源进入游戏的门禁

1. 建立资源记录：来源、作者、许可证、原始校验、改动、项目中的用途。
2. 先在样板中验证比例、轮廓、UV/材质、碰撞、遮挡和远近景可读性。
3. 角色需要可动模型与适配动作；概念图不直接算作游戏角色，不能用换色代替人物差异。
4. 记录渲染后端、分辨率、硬件/软件渲染条件和帧时间；没有目标机器实测时明确保留限制。
5. 先提供本地候选样板供评审，通过后再做批量替换；对外发布另需授权。不会仅以更大贴图分辨率宣称品质升级。

后续任务在每轮评审后按反馈调整，避免同时重写建造、居民、地图和渲染基础设施。

## 每轮固定工作流

1. 核对需求优先级：最新用户要求 > 原始当前任务大纲 > 较早交接 > 派生设计稿。代码/日志证明现状，不替代用户的设计选择；冲突写入决策门，不悄悄改口或回滚。
2. 在状态页只保留一个活跃里程碑：目标、排除项、涉及文件/函数、证据、停止条件。先查已有实现，列差距，再做最小改动；协作者明确文件归属，不重复编辑。
3. 按小闭环实施，不新增无用途的目录/框架。保留稳定 ID、状态所有者和兼容调用面；所有资源输入有来源、对账可验证，长期记忆不靠短期日志补造。
4. 先定向测试，再运行适用的完整回归/导出检查。要求退出码、无 `SCRIPT ERROR:` / `ERROR:`、对应 `*_OK:` 三者同时成立；已有失败、本轮失败、未运行分开记录。
5. 验收门：真实输入与中断/重复操作；实际渲染和人工观感；旧档迁移、新档重建、重复读取、失败不破坏状态；资产来源/许可/再分发。测试存档隔离，后台运行，不占用用户前台。
6. 功能、视觉、性能分别结论。性能缺证不能冒充通过；完整性能验收需固定硬件、后端、分辨率、构建模式、负载及同条件前后对比，记录 CPU/GPU、模拟、分位帧耗时、尖峰和内存。
7. 仅在较大里程碑通过后建立耐久检查点：准确基线、累计补丁（含新增文件）、文件校验、验证摘要与剩余限制；不为每个微小改动制造提交或存档。检查点保存方式遵守授权，私有原文/提示词/路径/凭据不进入仓库或发布包。
8. 环境重置后先恢复并校验最近已验证的累计补丁，再检查差异与复验；不用聊天记忆重写、不把旧远端当成最新成果。若检查点不可用，报告缺口，不伪称恢复完成。
9. 到达本轮停止条件后报告结果，再选下一大纲内里程碑；政策、权限或目标硬件缺失时暂停相关工作，继续不依赖该问题的验证。最新继续指令允许继续小步推进，但不等于自动建设全部远期系统。
